# 交互方案

目标：两个人在 iPhone 上单手完成开始、提交、审核和收付款；对象与金额始终清楚；连点或重试不会多记一笔钱。确认类成功后不提供反悔入口。

## 手机单手操作

- 主操作放在屏幕下半部或底部固定栏，按钮高度不小于 44pt，底部预留安全区，避免被 Home 指示条挡住。
- 一屏一件事：确认完工、拒绝完工、取消任务、标记付款、确认收款、拒绝到账都用页面或明确弹层，不把危险操作放在左上角或只靠滑动完成。
- 家务页把「待我审核」放在最上方；账本把应收、应付分栏，状态分段。
- 金额用较大字号；状态用文字标签，不只靠颜色。
- 表单输入时保证主按钮不被键盘挡住，可滚动到操作区。
- 不做以横滑为唯一操作的删除或结算。

## 核对其人与金额（不可逆操作）

下列操作一旦成功不可撤销，按钮旁（或提交前确认层）必须同时展示**对象**和**金额**，并写清后果。首版不做冲正、不做金额调整单，误操作记录保留在账本中，不覆盖、不删除、不在界面假装可以改回去。

| 操作 | 确认层要点 | 成功后 |
| --- | --- | --- |
| 确认完成 | 「确认后将记一笔应付工资：对象、金额。此操作不能撤销。」 | 生成工资；无撤销按钮 |
| 拒绝完工 | 原因必填；说明本次不入账，执行人可改说明后重提同一条 | 无反悔拒绝按钮 |
| 我已线下付款 | 「请确认已把下列合计线下付给某某」。列出明细与合计 | 进入待收款确认；付款人不能撤回该单 |
| 确认已收款 | 「确认已收到某某付来的合计。确认后结清，不能撤销。」 | 已结清；双方无撤销 |
| 未到账拒绝 | 原因必填；说明本结算单将保留，工资回到待付款，可重新结算 | 不是撤销结清（因此时尚未结清） |
| 取消进行中的家务 | 说明取消后不产生工资，且不能恢复 | 状态为已取消 |

执行人在「待确认」时可以把任务撤回为「进行中」。文案用「撤回提交，继续做」，不要写成「撤销确认」。该按钮只在待确认且当前用户是执行人时出现。

## 两类「待确认」的文案

| 场景 | 标题 | 说明 | 按钮 |
| --- | --- | --- | --- |
| 待确认完工 | 待确认完工 | 对方做完了，确认后才会记一笔应付工资 | 确认完成 / 拒绝 |
| 待确认收款 | 待确认收款 | 对方已标记线下付款，你确认收到后这笔才算结清 | 确认已收款 / 未到账，拒绝 |

付款人侧是「待付款 / 我已线下付款」，不要写成「确认工资」。拒绝原因占位符举例：「没做完 / 做的不是这项」「尚未收到这笔钱」。

## 勾选付款

- 只能勾选「已入账且待付款」的整笔工资，同向合并。
- 没有部分金额输入框。
- 勾选后调用 `POST /households/{householdId}/payments/preview`（只读、不占锁）。对象（`payer` / `payee`）、明细和 `total_amount_fen` 按后端结果展示；本地整数相加最多作为请求发出前的按钮可用判断，不能代替预览接口。
- 进入页、变更勾选、以及提交前都要拿到最新预览；预览与待提交清单不一致则中止并重新展示。
- 未勾选或预览合计为 0 时主按钮禁用。
- 双向都有欠款时，本页只出现「我应付给对方」的工资，反向工资走对方付款，不能在本页对冲。

## 空态

| 页面 | 空态文案 | 下一步 |
| --- | --- | --- |
| 家务：无模板且无任务 | 先添加一项家务并定价，再开始做 | 新增家务 |
| 家务：无待审核、无我的任务 | 没有进行中的家务 | 从下方模板「开始」 |
| 账本为空 | 开始并确认完工后会出现账目 | 去家务 |
| 无可付工资 | 不出现「去付款」或不进入付款页 | — |
| 关联页 | 先邀请对方，或填写邀请码 | 发起邀请 / 填写邀请码 |
| 解绑被拒 | 说明还有哪类未完成事项（进行中/待确认/已拒绝家务，或未结清工资） | 去家务或账本处理 |

## 加载、刷新与网络

- 列表首次进入用骨架屏。
- 提交类按钮进入 loading 并禁用，直到成功、失败或超时。
- 下拉刷新家务和账本。应用从后台回到前台，或页面重新可见时，刷新摘要和当前页，不依赖推送。
- 账务写操作必须在线。无网或超时提示「目前没有网络，账目需联网同步」，提供重试。不离线排队、不本地伪造已入账或已结清。
- 成功用轻量 Toast 后跳转或刷新；失败留在当页并保留已填内容（如拒绝原因）。

## 错误与冲突

- 字段校验错误显示在字段旁（账号名、密码、正整数金额、拒绝原因）。账号按 2–32 位字母/数字/下划线/中文校验，不要按手机号格式检查。
- 金额按「元」录入时，只允许两位小数，提交转换为分；0、空、负数、超过两位小数不能提交。
- 业务冲突（重复确认、工资已被占用、结算单已结清或已拒绝、邀请码无效/过期/已使用、有未结清账不能解绑）展示后端可直接阅读的 `message`，并立即重拉该资源。
- 若对方已先一步操作，当前页改为只读并展示最新状态，不报含糊失败。

## 防连点与防重复提交

以下写操作必须防连点；资金和状态变更类请求带 `Idempotency-Key`（一次点击/一次确认层生成 UUID，重试复用同一把钥匙）：

- 注册、登录
- 生成邀请、重新生成邀请、作废邀请、接受邀请、解绑
- 新增 / 编辑 / 停用模板
- 开始家务、提交完成、撤回提交、取消、确认完工、拒绝完工、拒绝后重提
- 创建结算单（标记已付款）
- 确认已收款、拒绝到账

规则：

1. 请求进行中按钮禁用；成功后按新状态隐藏该按钮，不再露出可点。
2. 同一幂等键应得到同一结果，不能生成第二笔工资或第二张有效结算单。
3. 不可逆操作的确认层本身也要防连点。

## PWA 与 iOS（首版接受）

- 在「我的」、以及关联成功后第一次进入家务时，用非打断式说明：用 Safari 打开，分享 → 添加到主屏幕后可全屏使用。
- 不做 Web Push，不承诺后台提醒。
- `viewport-fit=cover`，适配刘海/动态岛和底部安全区；准备一套浅色主屏幕图标。
- 主路径在竖屏一屏内能完成关键操作，避免横向溢出。

## 按钮用动作命名

主按钮使用：开始、提交完成、撤回提交、取消本次、确认完成、拒绝、我已线下付款、确认已收款、未到账拒绝、退出登录。不用单独一个看不出后果的「确定」作为主按钮（确认层里的最终按钮也要带动作名称）。
