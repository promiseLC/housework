# 页面、路由与导航

首版只做 iPhone 竖屏单栏。未登录、已登录未关联、已关联是三层入口，用路由守卫控制。切换或退出账号时清空 TanStack Query 与本地缓存，避免串账。

## 底部导航（已关联后）

三个主入口，贴屏幕底部，方便单手点按（与产品设计一致，不做第四个「待办」Tab）：

| Tab | 路由 | 职责 |
| --- | --- | --- |
| 家务 | `/chores` | 模板单价、开始一次家务、我进行中的任务、待我审核完工 |
| 账本 | `/ledger` | 应收 / 应付分开展示；区分待完工确认、待付款、待收款确认、已结清 |
| 我的 | `/me` | 账号、关联对象、解绑限制、退出、添加到主屏幕说明 |

角标只统计需要自己处理的数量，数字以 `GET /ledger/summary` 为准：待我审核完工、待我付款（有可勾选工资时）、待我确认收款。

解绑后该家庭历史只读，底部仍可进入账本查看旧记录，但不能再开始家务、审核或结算；与新人关联后进入新家庭工作区，旧流水不混入。

## 路由表

| 路径 | 页面 | 访问条件 |
| --- | --- | --- |
| `/login` | 登录（自设账号 + 密码） | 未登录 |
| `/register` | 注册（自设账号、密码、显示名） | 未登录 |
| `/pair` | 邀请 / 接受关联 | 已登录且当前无有效绑定 |
| `/chores` | 家务首页 | 已登录已关联（解绑后只读历史时不可开始新任务） |
| `/chores/new` | 新增家务模板 | 已登录且家庭有效 |
| `/chores/:id/edit` | 修改模板名称或单价 | 已登录且家庭有效 |
| `/tasks/:id` | 家务实例详情（提交、撤回、取消、确认、拒绝、重提） | 已登录，本家庭成员 |
| `/ledger` | 账本 | 已登录，本家庭成员（含已解绑的只读历史） |
| `/payments/new` | 勾选整笔工资并标记已付款 | 已登录且家庭有效，且有我应付的 `payable` 工资 |
| `/payments/:id` | 结算单详情（确认或拒绝收款） | 已登录，本家庭成员 |
| `/me` | 我的 | 已登录 |

未登录访问业务页跳到 `/login`；已登录未关联跳到 `/pair`；已关联访问登录/关联页跳到 `/chores`。注册成功后进入 `/pair`。接受前不可配置家务模板。

## 各页要做什么

### 登录 / 注册

登录注册使用自设唯一账号 `username` + 密码，不做手机号或邮箱强制，也不做短信验证。账号 2–32 位，只允许字母、数字、下划线和中文，不含空格（与 OpenAPI 0.1.2 一致）。注册另填显示名（1–20 字），密码 8–72 位。表单错误就地展示。退出或登录成功都清空上一账号缓存后再拉数据。

### 关联（`/pair`）

- 「发起邀请」：`POST /invites` 申请邀请码，大号展示明文和有效期（7 天），提供一键复制。若已有有效邀请，接口返回 `409`，应改为查看当前码或走重新生成，不要再创建第二条。邀请码单次使用（接受后失效）。
- 「填写邀请码」：输入对方邀请码并接受，成功后进入家务页。
- 刷新页面或再次进入「我的」、关联页时，用 `GET /invites/current` 读取当前邀请；pending 且未过期时响应含明文 `code`，继续展示并支持复制。明文以接口为准，不以创建当次会话缓存为唯一来源。
- 「重新生成」走 `POST /invites/regenerate`：旧码立即失效，展示新码。同一时间只保留一条有效邀请。没有可作废的邀请时不要调 regenerate，应走创建。
- 「作废邀请」走 `DELETE /invites/current`：只作废，不自动生成新码；需要新码时再创建。
- 不能邀请自己；对方已有绑定时接受失败并明确提示。

### 家务（`/chores`）

从上到下三块，需要自己处理的放上面：

1. **待我审核**：对方已提交、状态为待确认的实例。点进详情确认或拒绝。
2. **我的任务**：我是执行人的进行中、待确认、已拒绝（可改说明后重提）。进行中可继续提交或取消；待确认可查看，并可撤回为进行中。
3. **家务模板**：名称和每次单价。主操作是「开始」：开始后锁定本次名称、单价、执行人（我）和承担人（对方），进入进行中详情。另提供新增、编辑、停用。编辑页用一句话说明「改价只影响以后新开始的家务，已开始的记录不变」。停用后不能再开始，历史实例仍显示快照名称。

空模板时引导先添加一项，可预填常见名称供参考（换床单被罩、洗碗、扫地、拖地），工资必须由用户填写，不给默认金额。

### 家务实例详情（`/tasks/:id`）

始终展示：快照名称、锁定金额、执行人、承担人、状态、说明、审核历史（提交 / 确认 / 拒绝及原因）。按角色和状态露出操作，不该出现的按钮直接不渲染：

| 状态 | 执行人 | 对方（承担人） |
| --- | --- | --- |
| 进行中 | 提交完成、取消本次（取消需确认，不产生工资） | 只读 |
| 待确认 | 撤回为进行中（不是撤销审核结果） | 确认完成、拒绝（原因必填） |
| 已拒绝 | 修改说明后重新提交同一实例 | 只读，可见拒绝原因 |
| 已确认 / 已取消 | 只读 | 只读 |

确认、拒绝一旦成功，双方都不再看到撤销、反悔按钮。本人不能确认或拒绝自己的任务。

### 账本（`/ledger`）

顶部将「我应付」和「对方应付给我」分栏展示，不做抵扣后的净额作为唯一数字。下方用分段区分：

- 待完工确认（任务，尚未形成工资，标注「确认后才计入应付」）
- 待付款（`payable` 工资；若我是付款人，提供「去付款」）
- 待收款确认（进行中的结算单）
- 已结清
- 已拒绝的结算单（审计用，所含工资已回到待付款的，在待付款中再出现，本单标注已拒绝及原因）

点进任务或结算单详情。金额、对象、明细都要写清楚。

### 创建结算单（`/payments/new`）

仅付款人可进入。列出我应付且状态为待付款的整笔工资，可勾选一笔或多笔，不可输入部分金额、不可拆分单笔，不可勾选反向债务。

勾选变化后、以及点「我已线下付款」之前，调用 `POST /households/{householdId}/payments/preview`（只读，不占锁、不改状态）。页面按预览结果展示付款人、收款人、明细和 `total_amount_fen`，不以本地加总为权威数字。核对无误后再 `POST /payments` 创建结算单。预览成功后仍可能因并发占用导致创建失败，失败则重新预览并展示最新清单。

文案顺序：先线下把合计付给对方，再标记「已付款」。提交成功后进入该结算单详情，状态是待收款确认，不是已结清。创建后新确认的工资不会进入这张已创建的单，可在下次再勾选。

### 结算单详情（`/payments/:id`）

展示对象、明细、合计、标记付款时间、状态。收款人在待收款确认时可「确认已收款」或「未到账，拒绝」（原因必填）。确认成功后结清，双方都不再提供撤销。拒绝后本单保留为已拒绝，所含工资回到待付款。付款人不能代为确认收款，待确认期间也不能撤回该结算单。

### 我的（`/me`）

展示自己的账号（`username` 与显示名）、已关联对象、退出登录，以及 Safari「分享 → 添加到主屏幕」的简短说明。若有待接受且未过期的邀请，进入本页时请求 `GET /invites/current`，用返回的明文码展示并支持复制；提供「重新生成」（`POST /invites/regenerate`）和「作废邀请」（`DELETE /invites/current`，不作废后自动出新码）。解绑入口：存在进行中（含从待确认撤回后仍在进行中的任务）、待确认、已拒绝（仍可重提）的家务，或待付款 / 待收款确认的工资时，禁止解绑并说明先处理完；不能因为撤回后暂时没有未结工资就允许解绑。全部结清且没有上述未完成家务后才可解绑，旧历史只读。不做推送开关。
