# 状态设计

金额单位全程为整数「分」。前端只把分格式化为元（两位小数）展示；应付合计、结算金额一律以后端字段为准。勾选预览可以用整数分相加，提交后以服务端冻结的 `total_amount_fen` 为准。

实体命名与后端草案对齐：`chore_types`（模板）、`chore_tasks`（一次执行）、`wage_entries`（工资）、`payments`（结算单）。

## 关联与家庭

| 状态 | 含义 | 前端表现 |
| --- | --- | --- |
| 未关联 | 已登录，当前没有 `left_at` 为空的家庭成员关系 | 只能进入关联页 |
| 邀请待接受 | 我发出的邀请仍为 pending | 展示邀请码与有效期 |
| 已关联（家庭 active） | 两人绑定生效 | 三个业务 Tab，可开始家务和结算 |
| 已解绑（家庭 dissolved） | 双方结清后解除 | 旧历史只读，不能流入新关系；新绑定是新家庭 |

一人同一时间只能绑定一个对象。邀请码有期限、单次使用，接受后才创建家庭。不能邀请自己或第三人。

## 家务模板 `chore_types`

| 状态 | 含义 | 前端表现 |
| --- | --- | --- |
| 启用 `is_active=1` | 可以「开始」一次家务 | 列表可开始、可编辑 |
| 停用 `is_active=0` | 不能再开始 | 列表标已停用；历史实例仍用快照名称 |

改名、改价只影响之后新开始的实例。双方都可新增、改价、停用。

## 家务实例 `chore_tasks.status`

开始一次家务即创建实例，并锁定 `name_snapshot`、`unit_price_fen_snapshot`、`worker_user_id`（执行人）、`payer_user_id`（承担人）。每次执行独立实例，不做排班和多人分摊。

```
in_progress ──提交──► pending_confirm ──确认──► confirmed（同时生成唯一工资）
     │                      │    ▲
     │                      │    └── 已拒绝后改说明重提（同一实例）
     │                      ├──对方拒绝──► rejected
     │                      └──执行人撤回──► in_progress
     └──执行人取消──► cancelled
```

| 状态 | 含义 | 谁可操作 | 是否计入应付工资 |
| --- | --- | --- | --- |
| `in_progress` 进行中 | 已开始，快照已锁定 | 执行人：提交完成或取消 | 否 |
| `pending_confirm` 待确认 | 已提交，待对方审核 | 对方：确认或拒绝（原因必填）；执行人：撤回为进行中 | 否 |
| `rejected` 已拒绝 | 对方已拒绝 | 执行人：改说明后重新提交同一实例；快照不可改 | 否 |
| `confirmed` 已确认 | 已生成唯一工资 | 只读，不可撤销 | 是（工资走后续状态） |
| `cancelled` 已取消 | 仅能从进行中取消 | 终态，不生成工资 | 否 |

规则：

- 待确认不过期、不自动通过。
- 本人不能确认或拒绝自己的任务。
- 确认或拒绝一旦成功，界面不提供撤销、撤回确认、反悔拒绝。执行人在待确认时撤回为进行中，不是对已审核结果的撤销。
- 拒绝后重提不覆盖审核历史，详情展示每一次提交/拒绝记录。
- 重复提交、重复审核不得多生工资。一实例最多一笔工资，且只在确认成功时创建。

## 工资 `wage_entries.status`

```
payable → awaiting_receipt（纳入未拒绝的结算单） → settled
              └── 收款拒绝：结算单保留为 rejected，工资回到 payable
```

| 状态 | 含义 | 说明 |
| --- | --- | --- |
| `payable` 待付款 | 已入账，尚未被有效结算单占用 | 付款人可勾选，进入新结算单 |
| `awaiting_receipt` 待收款确认 | 已锁定在一张待确认结算单中 | 未结清；不可再被其他单勾选 |
| `settled` 已结清 | 收款人已确认到账 | 终态；禁止再结算、不可撤销结清 |

已确认工资不得改金额、不得删除。双方应收应付独立展示，不自动抵扣。

## 结算单 `payments.status`

付款人勾选**同方向**一笔或多笔完整的 `payable` 工资，创建结算单并标记已付款。不拆分单笔金额，不做自动把全部工资打包（与「不可拆分单笔」不是一回事）。

```
awaiting_receipt → settled
                → rejected（保留单据，释放工资为 payable）
```

| 状态 | 含义 | 谁可操作 |
| --- | --- | --- |
| `awaiting_receipt` 待收款确认 | 已标记线下付款，尚未到账确认 | 收款人：确认已收款，或未到账并填写原因拒绝 |
| `settled` 已结清 | 收款人已确认，本单工资同一事务结清 | 只读，无撤销 |
| `rejected` 已拒绝 | 收款人否认到账；本单留作审计 | 只读；工资已回到待付款，可重新勾选开新单 |

付款人不能自行撤回已创建的结算单，也不能代替收款人确认。空选或合计为 0 不能提交。

## 解绑相关状态

存在任一则禁止解绑并提示先处理：任务为进行中、待确认或已拒绝（已拒绝仍可重提）；工资为待付款或待收款确认。把待确认撤回为进行中后，只要该任务还在进行中，仍禁止解绑，不能因为当时没有未结工资就放行。全部结清且没有上述未完成家务后方可解绑，历史只读，不提供改账或补记。

## 待办信息与文案区分

「待确认完工」还不是工资；「待确认收款」是已经线下付款、只差收款确认。两处标题、颜色、按钮必须分开，账本也不用一个「待处理金额」混在一起。

| 分组 | 数据 | 主操作 |
| --- | --- | --- |
| 待我确认完工 | 对方提交且 `pending_confirm` 的任务 | 确认完成 / 拒绝 |
| 待我付款 | 我为付款人且 `payable` 的工资 | 去付款（勾选整笔） |
| 待我确认收款 | 我为收款人且 `awaiting_receipt` 的结算单 | 确认已收款 / 未到账拒绝 |

## 界面状态（每个可请求页面）

| 界面状态 | 何时 | 表现 |
| --- | --- | --- |
| `loading` | 首次进入、下拉刷新、提交中 | 骨架屏或按钮 loading，写操作按钮禁用 |
| `empty` | 列表无数据 | 针对性空态 + 一个明确下一步 |
| `error` | 网络失败或 5xx | 说明原因，提供重试 |
| `conflict` | 状态已变化、重复提交、无权 | 展示后端 `message`，立即刷新该资源为只读或最新可操作态 |
| `ready` | 数据可用 | 正常操作 |

TanStack Query 以服务端数据为唯一来源。写操作成功后失效并重拉摘要、列表、详情，不在本地猜测下一个状态，成功前不把界面提前显示成已成功。
