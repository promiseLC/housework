# iPhone 体验检查方案（首版）

- 状态：**已准备，全部未执行**
- 准备时间：2026-11-20（Asia/Shanghai）
- 对应清单第 7 节 I1–I17，以及 `docs/frontend/interactions.md`、`docs/frontend/pages-and-navigation.md`
- 时机：与集成回归一起，在产品统一集成后由测试独立执行。当前没有可测页面，不得把未执行改成通过。

首版只要求 iPhone 竖屏主路径可用：Safari 打开，并尽量「添加到主屏幕」后在全屏窗口再跑一遍关键路径。不依赖推送和后台提醒。账务写操作必须在线，失败可安全重试，成功前不得假显示已成功。

---

## 1. 设备与准备

- 至少一台 iPhone（有刘海或动态岛更佳），系统 Safari。
- 配对账号用两台手机，或一台手机加一个清理过的备选浏览器资料；不要在同一 Safari 同时保持两个登录态来代替「对方」。
- 测试前记录：机型、iOS 版本、是 Safari 还是主屏幕图标、前端/后端构建版本。
- 测试账号与金额用 [测试数据.md](./测试数据.md)。
- 检查「我的」中的添加到主屏幕说明：用 Safari 打开 → 分享 → 添加到主屏幕。

---

## 2. 执行方法

每条先在 Safari 看，再在添加到主屏幕后的窗口看（I1 本身除外）。主路径（注册/登录、邀请、开始家务、提交、确认、预览付款、确认收款）至少在主屏幕窗口完整走一次。

记录遮挡、横向溢出、错误文案、假成功、缓存残留。金额与对象必须写清，避免只记「看起来没问题」。

## 4. 文案与按钮（穿插观察）

主按钮应能从字面上看出后果，例如：开始、提交完成、撤回提交、取消本次、确认完成、拒绝、我已线下付款、确认已收款、未到账拒绝、退出登录。不要用看不出后果的单独一个「确定」作为主操作。

两类「待确认」必须能分清：待对方确认完工（尚未形成工资）与待确认收款（结算单未结清）。
