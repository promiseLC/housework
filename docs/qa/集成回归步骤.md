## 0. 开始前检查（未就绪则整轮阻塞）

1. 存在已集成的前端 + 后端可访问地址（开发环境），MySQL 为开发库。
2. 构建或提交版本已记录。
3. 按 [测试数据.md](./测试数据.md) 准备两对家庭和一个未绑定账号，或确认可现场注册出这组数据。
4. iPhone 检查按 [iPhone体验方案.md](./iPhone体验方案.md) 准备：至少一台 iPhone 的 Safari，并尽量添加到主屏幕；可用两个浏览器资料或两台手机分别登录配对账号。
5. 不开始本步骤清单之外的破坏性操作。

## 1. 冒烟（先确认主路径能走通，再进入高风险）

顺序不要跳：

1. 分别注册并登录家庭 A 的两个账号，用邀请码完成关联（A7、A8 可在此顺手看复制与重生成，但高风险项放后面复测）。
2. 创建模板「洗碗」等，金额由测试数据填写，开始一次家务并提交。
3. 对方确认完工，生成待付款工资。
4. 付款人勾选整笔，先预览再标记已付款；收款人确认已收款后结清。

任一环节无法继续，则记录阻塞，不把后续项标通过。

## 2. 高风险优先（对应清单 H1–H13）

建议按此顺序，便于定位串账和丢债：

| 顺序 | 清单 | 做法要点 |
| --- | --- | --- |
| 1 | H3、H12 | 执行人不能确认自己的完工；确认/拒绝成功后无撤销。待确认仅执行人可撤回为进行中。 |
| 2 | H2、B2、B6 | 对提交、确认、预览后创建、确认收款使用连点、重复提交和相同幂等键；并发撤回与审核只允许一方成功。 |
| 3 | H7、M3 | 开始实例后改模板单价，旧实例与已入账工资金额不变。 |
| 4 | H4、H13、P3、B9 | 预览不占锁、不生成结算单；创建后仍为待收款确认；合计以后端预览为准。 |
| 5 | H5、P9、P12 | 收款拒绝后结算单保留，工资回到待付款且金额不变，家务仍为已确认，可再次付款。 |
| 6 | H6、H9、P2、P10 | 双方互欠时分开展示、不抵扣；一张结算单只能含同方向整笔工资，不能拆分单笔。 |
| 7 | H8、A9、A10 | 进行中、待确认、已拒绝（可重提）以及未结工资均阻止解绑；撤回为进行中后，只要任务仍在进行中，即使没有未结工资也阻止。 |
| 8 | H1、H10、A12 | 家庭 B 不能读到家庭 A 的任务和账；同设备切换账号无缓存残留。用遍历 ID 验证越权失败。 |
| 9 | H11 | 账本四段（待完工确认 / 待付款 / 待收款确认 / 已结清）与明细加总一致，待完工确认不计入应付。 |

## 3. 分模块补全（高风险通过或记录后再补）

1. **账号与邀请（A1–A8、A11–A12、B7–B8）**：错误/过期/已使用邀请码；不能邀请自己；已绑定不能再绑第三人；`DELETE` 只作废不生成；`regenerate` 后旧码立即失效。
2. **家务（M、C）**：金额校验（最低 1 分）；已拒绝改说明后重提同一实例且不产生第二笔工资；进行中可取消；已确认不可改删。
3. **收付款（P）**：空选不能提交；付款人不能代确认收款；已付款后付款人不能撤单；已结清不能再结算。
4. **解绑与历史（A9–A12）**：全部结清且无未完成家务后才允许解绑；旧历史只读，不流入新关系。
5. **iPhone 体验**：按 [iPhone体验方案.md](./iPhone体验方案.md) 跑 I1–I17，可与上面主路径穿插，但安全区、键盘、PWA、弱网要单独看一遍。
