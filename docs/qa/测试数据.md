## 4. 场景数据（建议制造顺序）

下列金额均为分。每造完一批，记下任务 ID、工资 ID、结算单 ID，供隔离和幂等复用。

| 编号 | 目的 | 做法 | 期望快照 |
| --- | --- | --- | --- |
| D1 | 主路径结清 | 小明开始并提交「洗碗 800」，小红确认；小红预览后付款 800，小明确认收款 | 洗碗工资已结清 800 |
| D2 | 待确认撤回 | 小明开始「扫地 600」并提交，再撤回为进行中 | 无工资；任务进行中；此时解绑应失败（A10） |
| D3 | 完工拒绝并重提 | 小明提交「拖地 1000」，小红拒绝并写原因「还没拖完」；小明改说明后重提同一实例，小红再确认 | 一笔工资 1000，不是两笔；审核历史保留 |
| D4 | 模板改价 | 在 D3 开始之后，把「拖地」模板改为 1200 | 该实例与工资仍为 1000 |
| D5 | 同向合并付款 | 再让小明完成「扫地 600」并入账，使小红同时欠 拖地 1000 + 扫地 600 | 预览合计 1600，创建一张结算单；不拆分 |
| D6 | 收款拒绝 | 对 D5 结算单，小明选「未到账拒绝」并写原因 | 结算单保留为已拒绝；1000 与 600 回到待付款 |
| D7 | 反向债务不抵扣 | 小红执行「换床单被罩 1500」，小明确认入账 | 账本同时显示小红应付 1600（若 D6 已释放）、小明应付 1500，互不抵消；不能放进同一张结算单 |
| D8 | 解绑拦截矩阵 | 在仍有进行中/待确认/已拒绝或未结工资时尝试解绑 | 均应被阻止，记录不被关闭 |
| D9 | 解绑成功与只读 | 先取消仍在进行中的任务，把未结工资全部走完预览→付款→确认收款后解绑 | 历史只读；再与新人绑定不得带入旧账 |
| D10 | 隔离 | 用家庭 B 账号猜测或使用家庭 A 的任务/工资/结算单 ID | 不可读不可改 |
| D11 | 切账号 | 同一 Safari 或主屏幕应用先登录小明再退出登录小红 | 无小明的列表、金额、邀请码残留 |

非法操作抽样（不必另造家庭）：空选付款、拆分 800 只付 300、付款人点确认收款、执行人确认自己的完工、已结清再付一次。

## 5. 账本合计校对（家庭 A 示例）

在 D7 完成、D5 被拒绝且尚未重新付款时，预期口径如下（执行时以当时未结清数据为准，下列为对照样例）：

- 待完工确认：不计入应付。
- 小红应付小明：拖地 1000 + 扫地 600 = 1600（待付款）。
- 小明应付小红：换床单被罩 1500（待付款）。
- 已结清：洗碗 800（D1，若已走完）。
- 已拒绝结算单：D5 那张仍可见原因，但工资已回到待付款，不要把 1600 再加进待收款。

核对账本汇总里的待付款、待收款、已结清与列表明细，禁止浮点误差。
