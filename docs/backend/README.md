# 后端契约草案（暂不编码、不建仓库、不推送）

对应产品设计：`/workspace/household-pay-planning/product/2026-11-20-household-pay-design.md`

本目录文件：

- [data-model.md](./data-model.md)：数据模型、状态机、约束与幂等
- [openapi.yaml](./openapi.yaml)：OpenAPI 3.0 接口契约，供前端与测试对齐

技术栈按已确认方案：**Python FastAPI + MySQL**。金额一律用整数分，禁止浮点。首版不接支付、不部署。实现时再补数据库迁移与无密钥的环境样例。

与产品提案一致的后端立场：

- 同意首版只勾选**同方向整笔工资**合并付款，不拆分单笔，也不做自动抵扣。
- 价格快照时点按产品设计：在**开始一次家务**时锁定名称、单价、执行人和承担人；改模板或拒绝后重提说明，都不得改这笔快照。
- 收款人拒绝「已付款」时保留该结算单，并释放工资回到待付款，以便重新勾选结算。

- 登录为用户自设的唯一 `username` + 密码，不强制手机号或邮箱，首版不做短信。
- 待确认完工时，仅执行人可将任务从 `pending_confirm` 撤回为 `in_progress`；这不是对已确认或已拒绝结果的撤销。首版不提供确认后冲正、撤回确认、撤回已付款或撤销结清的接口。

- 邀请人在邀请码 pending 且未过期时可再次查看并复制明文；支持作废并重新生成，同一时间只能有一条有效邀请。
- 付款前提交 `POST /households/{householdId}/payments/preview` 核对对象、明细和合计；预览不占锁、不改状态。
- 解绑拦截：进行中、待确认、已拒绝（可重提）任务，以及待付款/待收款确认工资均阻止；撤回为进行中后仍阻止。结算占用只用 `locked_payment_id`，不对 `payment_items.wage_entry_id` 做永久全局唯一。
