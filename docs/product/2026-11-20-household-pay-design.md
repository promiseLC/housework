# 双人家务计酬首版产品设计

## 已确定范围
用户2026-11-20授权开发。两个独立账号先关联；家务按次定价，执行人赚工资，另一方承担。线下支付，付款方标已付款后，收款方确认才结清。不自动抵扣、不接支付、不部署、不依赖推送。
React + TypeScript + Vite + React Router + TanStack Query + Ant Design Mobile，iPhone PWA；Python FastAPI + MySQL；私有GitHub单仓库frontend/backend/docs。

## 产品默认边界
以下细节由产品按用户授权确定，开发评审发现冲突先内部修正文档，不冒称用户逐项指定。
用账号和密码注册登录，不强制手机号或邮箱，首版也不做短信验证；账号为用户自设的唯一登录名，密码只存安全哈希。邀请码有效期7天、单次使用，对方接受后才创建家庭，接受前不能配置家务。邀请仍为待接受且未过期时，邀请人进入「我的」可再次查看并复制明文邀请码，以便发给对方；也可作废后重新生成，新旧码不能同时有效。一人同一时间只能绑定一个对象，不能邀请自己或第三人。后端按登录身份验证家庭归属，切换账号清理前端缓存。
解绑拦截必须同时覆盖：进行中、待确认、已拒绝（仍可重提）的家务，以及待付款或待收款确认的工资。把待确认撤回为进行中后，只要该任务还在进行中，仍禁止解绑，不能因为当时没有未结工资就放行。全部结清且没有上述未完成家务后才可解绑；旧历史只读，不得迁入新关系。
家务名称可参考换床单被罩、洗碗、扫地、拖地，工资由用户填写。模板可编辑、停用，金额为正整数分。开始一次家务时锁定名称、价格、执行人，改模板不改旧任务。每次执行独立建实例，不做排班和多人分摊。
执行人提交完成，另一人确认才生成工资；本人不能自确认。拒绝填写原因；待确认不过期、不自动通过，也不计入应付工资。已确认工资不得改金额或删除。

### 确认后不可撤销与首版纠错
完工确认或拒绝一旦成功，双方都不能撤销该决定；界面不提供撤销、撤回确认、反悔拒绝按钮。付款确认与收款确认同样：标记「已付款」后，付款人不能自行撤回该结算单；收款人确认「已收款」后双方都不能撤销结清。收款人拒绝到账不视为撤销结清，只是把仍未结清的工资重新释放为待付款，该结算单保留为已拒绝审计记录。
待对方确认完工前，仅执行人可将该次任务从「待确认」撤回为「进行中」，这不是对已确认或已拒绝结果的撤销。
首版不做冲正、不做金额调整单、不提供管理员改账入口。若发生误确认、误拒绝或误结清，错误记录保留在账本中，不覆盖、不删除、不在界面假装可以改回去。使用前须在确认按钮旁提示核对对象与金额；有争议先线下沟通，后续版本再单独立项做冲正。产品与测试均不得将冲正写成已支持能力。

## 状态与付款闭环
家务：进行中、待确认、已确认、已拒绝、已取消。进行中可取消；被拒绝可修改说明后重新提交同一实例，保留审核历史。重复提交和重复审核不得多生工资。
工资：待付款、待收款确认、已结清。双方应收应付分别展示，不补差抵扣。
付款方在线下付款后，勾选同方向一笔或多笔完整工资，先预览对象、明细和合计金额，确认后再创建结算单并标记已付款。首版不拆分单笔工资；所选工资锁定，仍不能算结清。接口需提供付款预览，以后端计算结果为准。只有对应收款人确认到账，结算单及工资才在同一事务内结清。
未到账时收款人拒绝并写原因，保留该结算单，释放工资恢复待付款。未确认不自动结清；已结清工资禁止再结算。付款人不能代替收款人确认。

## 页面与交互
登录注册、邀请关联；关联后三个主入口：家务、账本、我的。家务展示单价、开始、提交及待我审核；账本分应收应付，并区分待完工确认、待付款、待收款确认、已结清；我的提供关联、解绑限制、退出和添加主屏幕说明。
所有金额操作清晰显示对象、金额、明细；提交防连点，加载/空态/错误清楚，成功前不假显示已成功。账务写操作必须在线，失败可安全重试，不离线排队；刷新以后端状态为准。

## 核心验收
1. 两账号关联后仅本家庭可见；第三账号遍历ID不能越权。
2. 模板改价不改已开始实例；一实例最多一笔工资。
3. 本人不能确认自身完工；待确认和已拒绝不计入工资。
4. 标付款不是结清，只有对应收款人确认才能完成。
5. 重复点击、重试和并发不能重复入账、占用或结清。
6. 双向债务独立、不自动抵扣；金额分存储，不用浮点数。
7. 数据库事务、唯一约束和服务端状态检查保护账目。
8. iPhone核心流程无横向溢出，按钮/金额清楚，账号切换不串缓存。
9. 测试报告明确已执行、未执行、通过、失败和阻塞。

## 交付与分工
产品维护本设计及验收；后端先给模型和OpenAPI契约；前端对齐页面状态与契约；测试准备高风险和移动端体验清单，代码完成后实际执行。
实现顺序：账号关联、家务定价与完工、收付款闭环、PWA体验与回归。每阶段写清feat/fix/test/docs提交，不用一次性含糊提交。提供数据库迁移、开发启动说明和无真实密钥的环境样例。仅开发环境运行，用户未授权上线或付费。
